# 星泊豪华大巴房车 · 交互式三维展示

StarPark Luxury Bus RV — a browser-viewable 3D model of a procedurally generated
luxury coach conversion. Everything you see (geometry, materials, the studio floor)
is generated by a Blender `bpy` script; no external model, texture or HDR file is
imported at any point in the pipeline.

## Three ways to look at it

| 模式 | What it does |
| --- | --- |
| **外观环绕** | Turntable orbit around the whole vehicle, with nine preset angles (three-quarter hero, side elevation, rear, roof plan, front close-up, wheel close-up, rear axle, low-slung garage bay, and a sectioned view of the wet-bath module). Drag to orbit, wheel to zoom, right-drag to pan. |
| **车内漫游** | First-person walk *inside* the coach. Six preset stations — 驾驶席 / 全景过道 / 会客沙发 / 厨房 / 后舱回望 / 上层卧铺 — plus four 看向·前/后/左/右 buttons. Drag to look around, `W A S D` or the arrow keys to move, wheel to change the field of view. |
| **剖面透视** | A clipping plane slices the body lengthwise so the cabin reads from outside; the slider moves the cut, and the glazing clears up so the interior stays visible through the shell. |

Deep links work: `?mode=interior&station=2`, `?mode=orbit&view=5`,
`?mode=section&cut=0.0`, `?mode=section&view=8` (the sectioned wet bath).

## Running locally

The page uses ES modules and an import map, so it has to be served over HTTP
rather than opened from `file://`:

```bash
cd <this folder>
python -m http.server 8080
# then open http://127.0.0.1:8080/index.html
```

Any static host works — there is no build step, no bundler and no network
dependency. `three.js` is vendored under `vendor/`, so the page also runs offline.

## Layout

```
index.html                 page shell, import map, HUD
styles.css                 dark "magazine" UI
app.js                     scene setup, materials, camera modes, first-person controller
assets/starpark_rv.glb     the model — 38 meshes, ~88k triangles, 2.5 MB
vendor/three/              three.js r169 (build + the four addons actually used)
source/build_rv.py         the Blender generator (~1470 lines of bpy)
source/export_web.py       flattens procedural materials and writes the GLB
source/starpark_bus_rv_final.blend
source/render_final.png    1920x1080 Eevee reference render
```

## Rebuilding the model from scratch

Requires Blender 5.2.x.

```bash
blender -b -P source/build_rv.py                          # build, render, save the .blend
RV_TAG=myshot RV_RES=1920,1080 RV_SAMPLES=96 blender -b -P source/build_rv.py
blender -b source/starpark_bus_rv_final.blend -P source/export_web.py
```

`export_web.py` rewrites `assets/starpark_rv.glb`. Blender's procedural node graphs
do not survive glTF, so the exporter flattens each material to its base colour and
emissive strength before writing; the viewer then re-introduces the glass
transparency and the studio lighting in `app.js`.

## Notes on the model

* Metres, Y-up after the glTF `export_yup` conversion. The nose points to `+X`;
  the entrance door is on `+Z`, the (left-hand-drive) driver on `-Z`.
* Bodywork is a profile lofted with tumblehome and a front shear, then cut by 25
  aperture solids applied **one at a time** — a joined union of those cutters is
  self-intersecting, and Blender's EXACT boolean solver answers that with a
  degenerate stub mesh.
* Reference render: Eevee, 96 samples, AgX medium-high contrast, fog-glow pass.
